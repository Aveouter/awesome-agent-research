# Research Direction Map

更新时间：2026-09-14

## 暂定主线

**可靠、自适应的多 Agent 协同**

核心问题：Agent 如何判断自己会不会、是否需要协作、应该找谁、何时验证，以及何时停止？

```text
任务
  ↓
能力与置信度估计（元认知）
  ↓
单 Agent / 多 Agent 路由
  ↓
角色、拓扑、通信预算与验证策略
  ↓
成功或失败轨迹
  ↓
经验筛选、记忆更新与遗忘（持续学习）
```

## 三个方向如何分工

| 方向 | 在博士主线中的角色 | 当前最具体的问题 | 风险 |
|---|---|---|---|
| 多 Agent 协同 | 系统主线和实验载体 | 动态组队、信息共享、验证、成本控制 | 容易退化成框架或提示词工程 |
| 元认知 | 决策机制 | 能力自评、失败预测、是否求助、何时停止 | 定义不统一，静态置信度不等于完整元认知 |
| 持续学习 | 长期扩展 | 经验选择、记忆更新、跨任务迁移和遗忘 | 周期长，容易混淆检索增强与真正学习 |

## 当前判断

1. 多 Agent 的关键不是数量，而是何时协作以及如何避免协作失败。
2. 元认知最好作为可测量的机制，不宜只停留在“反思”概念。
3. 持续学习应先从外部记忆的选择、更新和遗忘做起，再考虑参数更新。
4. 所有实验必须包含强单 Agent、best-of-N、固定协作策略和成本指标。
