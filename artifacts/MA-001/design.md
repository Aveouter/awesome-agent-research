# MA-001：验证实验设计

- Paper ID：MA-001
- Critic：[C1 预算混杂](critic.md)
- 性质：个人提出的验证方案，未执行；不是作者实验结果。

## 1. 验证目标

检验表 5 中 prompt 干预的收益是否超出增加推理资源的效果。首轮固定拓扑，不同时测试在线路由。

## 2. 核心假设与反证条件

H1：相同总 Token 上限下，增加结构化验证的 prompt 在 GSM-Plus 上优于原 prompt 与独立采样。若相对两个对照的配对改善不稳定或预算匹配后消失，则不能支持 H1；若置信区间包含零，结论为证据不足，而非已证明无效。

## 3. 实验设计

- 对应质疑：C1。自变量仅为预算分配/验证策略。
- 对照：A 原 AG2；B 同拓扑改验证 prompt；C 同模型独立解题后多数投票。另加单 Agent 工具解题作为参照，保持可用工具一致。
- 数据：GSM-Plus 按原始题目家族划分校准集与测试集，避免扰动版本跨集合。建议 20 题校准、50 题试验，3 个固定随机种子；这只是可行性规模。
- 控制：同一可用模型快照、题目、工具权限、采样温度、答案解析器；每臂总输入+输出 Token 上限一致，所有规划、验证、聚合调用均计入。超限和超时计失败。
- 预算：先用校准题估计长度并冻结每题上限；试验输出以预算—成功率曲线比较，同时记录实际消耗。不执行未确定金额上限的付费调用。
- 指标：最终答案 exact match、输入/输出 Token、墙钟时延、费用；题目级配对差及 bootstrap 区间。按原始题目家族聚类抽样，不将种子当独立题目。
- 预期：B 在相近实际预算上改善 accuracy。反证：优势只存在于更多 Token，或 C 达到相同结果。

## 4. 公平性与泄漏控制

多数投票的平局处理预先固定，不能用正确答案挑最优输出。评分答案仅供离线评价。任何 prompt 调整只在校准集完成。在线标签与完整轨迹标签不混用。

## 5. 优先级

先核对论文配置和数据 revision，再完成低成本 pilot；只有效果与预算关系清楚后才增加模型或题量。

## 6. 第一批最小实验

先验证一个题目的计费、截断和评分链路，再跑预先冻结的配对试验。开始复现前建立 Experiment issue，补运行命令、commit 和预算，之后才写 spec。代码路径当前未确认，不虚构入口。

## 7. 不进入本轮的扩展实验

新拓扑、失败分类器训练、在线路由、长期记忆、跨模型迁移。
