# 文献文件与 Git 边界

## 两个项目的职责

| 位置 | 唯一职责 | Git |
|---|---|---|
| `D:\paper` | PDF、Zotero 数据、导出、全文提取、缓存和本地任务交接 | 整个目录不纳入 Git |
| 本研究仓库 | Markdown 笔记、论文总表、引用、研究判断及必要维护脚本 | 独立分支和 PR |

Zotero 管理条目和附件；附件通过 Zotero 内置坚果云 WebDAV 同步。不得让文件同步客户端直接同步 Zotero 数据库。账号配置不进入研究任务的扫描范围。同步与备份分别安排，不将同步成功视为完成备份。

本地结构：`inbox/` 暂存待导入 PDF；`exports/` 保存导出；`work/<paper-id>/` 保存全文提取、OCR 和临时交接；`cache/` 保存可重建缓存；`Zotero/` 与 `ZoteroProfile/` 由应用维护。Agent 可以读取任务明确指定的附件，不直接增删改 Zotero 内部文件。

以论文 ID 关联 DOI/arXiv ID、原文版本、Zotero 条目标识和唯一主笔记。本机附件路径留在本地映射中。正式状态以 `papers.md` 为准；元数据变化需核对 `references/library.bib`，不双向自动覆盖人工内容。

## 仓库允许的内容

- Markdown 笔记、分析、研究计划、整理后的实验结论及文档。
- BibTeX 引用，以及必要的 Python、Shell、PowerShell、YAML、JSON、TOML 文本源码/配置。
- 明确列出的 Git 配置、许可证和仓库钩子；单个文件最多 1 MiB，必须为 UTF-8 文本。
- 小型复现脚本和配置可以保留；大型实现使用独立实验仓库，通过链接关联。

禁止 PDF、数据库、图片、压缩包、模型、原始数据/轨迹、全文 OCR/提取副本、账号配置、密码和令牌。文献摘要和有来源的必要短引文可以进入笔记，整篇原文不能改后缀后提交。不使用 Git LFS 绕过此边界；不添加指向本地资料的符号链接或子模块。

`scripts/check_git_boundary.py` 是机器可执行规则：类型白名单、目录限制、大小、UTF-8、常见二进制签名和部分明显凭据格式。规则不能识别所有明文密码或判断一段文字是否为全文抄录，仍需审阅实际 diff。新增合法文件类型时通过维护 PR 调整规则及测试，不绕过检查。

## 首次启用本地检查

在克隆目录中使用可用的 Python 3 执行：

```bash
python scripts/install_git_hooks.py
python scripts/check_git_boundary.py --history HEAD
```

安装器只设置本仓库的 Git 配置，不修改全局配置；已有其他 hooksPath 时停止并保留原配置，需手动整合。记录的 Python 路径不进 Git。hooksPath 使用绝对路径并由关联 worktree 共享，因此该安装目录需要保留；重新克隆或移动安装目录后重新配置。钩子文件必须保持 LF 和可执行位。

- `pre-commit` 检查完整暂存区的 Git blob，工作区尚未暂存的修改不会掩盖违规。
- `pre-push` 检查将引入的所有提交快照，新远端分支检查完整可达历史。新增后删除的违规文件仍阻止推送；只删除工作区文件不能清除历史。远端基准在本地缺失时先 fetch 后重试。
- CI 检查 PR/推送范围的每个快照以及最终树；CI 发生在上传之后，不能替代本地检查。分支保护是否强制此检查需单独核实，不能仅凭工作流存在就宣称强制生效。

本地 hooks 可以被 Git 参数绕过，因此它们是防误操作措施，不是不可绕过的权限隔离。Agent 不得使用 `--no-verify`、临时禁用 hooks 或改后缀来规避规则。检查失败时定位源文件，保留本地资料，修复待提交/待推送内容后重试；涉及历史重写或已上传敏感数据时先说明影响，不擅自强推或删除。

## 多客户端规则与协作

研究规则只在仓库的 `AGENTS.md`、`CONTEXT.md`、`WORKFLOW.md` 和论文技能中维护。`CLAUDE.md` 引用 `AGENTS.md`。本地 paper 项目只维护本地职责并指向研究仓库，不复制完整研究 workflow。客户端是否加载规则需要在实际新会话中验证，模型名称不代表自动加载能力。

任务开始时核对工作目录、分支和最新 main。默认一篇论文一条分支、一个 PR；多论文共用的边界/脚本维护单独提交维护 PR。需要并行协作时独立 worktree，避免多人同时修改共享总表；合并前更新基准并运行验证。不要自动启动额外 Agent。

交接至少包含论文 ID、原文版本、已核实证据位置、未解决问题、变更文件、分支/PR、检查结果和下一步；临时交接留在本地 `work/`。人工阅读状态与证据等级分开，不回退用户已经确认的阅读进度。
